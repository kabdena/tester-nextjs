# Спека 001. Локальный профиль студента, вход через Telegram и рост

- **Статус:** черновик, ждёт решений владельца (раздел 9)
- **Дата:** 24.11.2026
- **Источник:** брейншторм четырёх агентов (продукт, ИБ, рост, архитектор-критик) по данным Яндекс Метрики за май 2025 — ноябрь 2026

## 1. Проблема

Студенту нужен не «личный кабинет», а три вещи:

1. **Не загружать** один и тот же .docx перед каждой попыткой.
2. **Видеть, готов ли он:** какие вопросы банка уже знает, где ошибается, растёт ли результат от попытки к попытке.
3. **Вовремя вспомнить** про тестер перед сессией.

Пункт 1 закрыт в прошлом релизе: файлы хранятся в IndexedDB (`uploadedFiles`), прогресс теста переживает перезагрузку. Пункты 2 и 3 не закрыты.

| Явный трафик из Telegram за всё время | 160 визитов (1,4%) | Тезис «многие заходят через Telegram» не подтверждён |

### Обнаруженный дефект ИБ

`src/app/api/upload/route.ts` в продакшене молча пересылает каждый загруженный .docx в Telegram-чат владельца, а пользователь видит нейтральное «успешно».

- В файлах могут быть банки вопросов вуза, ФИО и ИИН, имя автора в метаданных `docProps/core.xml`.
- Это сбор и трансграничная передача данных без согласия: серверы Telegram вне РК, закон РК «О персональных данных и их защите» требует согласия и локализации. Это не юридическое заключение.
- Эндпоинт открыт: любой может слать в чат владельца произвольные файлы от имени его бота.
- Пока этот поток есть, заявление «данные не храним» ложно.

## 2. Принцип данных (нормативный)

> Содержимое тестов, ответы и результаты хранятся **только на устройстве пользователя**. Наш сервер не принимает, не записывает и не пересылает пользовательский контент и не ведёт базы пользователей. Запрос с содержимым теста на наш сервер — дефект.
>
> Данные покидают устройство только **по явному действию пользователя**, с указанием, куда они уходят:
> 1. файл экспорта, который пользователь сохраняет сам;
> 2. *(Фаза 1, опционально)* синхронизация прогресса в Telegram CloudStorage — только хеши вопросов и статусы, без текста; включается и стирается пользователем.
>
> В ссылках, логах и аналитике нет идентификаторов пользователя (tg id, username) и содержимого вопросов. Вебвизор не включать.

**Проверка:** в DevTools при загрузке файла и прохождении теста нет исходящих запросов с содержимым файла.

## 4. Пользовательские истории (Фаза 0)

- **US-1.** Как студент, я хочу быть уверен, что мой файл никуда не уходит, и прочитать об этом коротко на сайте.
- **US-2.** Как студент, я хочу видеть историю своих попыток по каждому файлу: дату, сколько вопросов, процент, время.
- **US-3.** Как студент, я хочу пройти тест только по вопросам, в которых ошибался.
- **US-4.** Как студент на iPhone, я хочу, чтобы мои файлы и история не пропали к следующей сессии.
- **US-5.** Как студент, я хочу одной кнопкой отправить в чат группы ссылку на тестер с готовым текстом на русском или казахском.
- **US-6.** Как владелец, я хочу знать, сколько людей приходит из Telegram и по ссылкам шаринга.

- Есть страница «Данные и приватность» (`/privacy`): что хранится и где, что Метрика собирает обезличенную статистику, как всё стереть. Ссылка в футере.
- **Приёмка:** при загрузке файла во вкладке Network нет запросов, кроме статики и Метрики.

### R2. Стабильные идентификаторы (основа для R3)
- `fileId` = SHA-256 содержимого .docx (WebCrypto).
- `questionId` = SHA-256 от нормализованного текста вопроса + нормализованного текста правильного ответа.
- Нормализация: нижний регистр, `ё→е`, схлопнутые пробелы, без завершающей пунктуации.
- Миграция существующего `uploadedFiles` (без `fileId`): ID считаются при первом чтении.
- **Приёмка:** повторная загрузка того же файла даёт тот же `fileId`; вопрос, перенесённый в другой файл без изменений, даёт тот же `questionId`.

### R3. История попыток и «Работа над ошибками» (US-2, US-3)
- По завершении теста (кнопки «Завершить тест» / «Показать результаты») в IndexedDB пишется попытка: `{ id, startedAt, finishedAt, fileIds[], total, answered, correct, elapsedSeconds }`.
- Для каждого вопроса хранится последний статус: `questionId → { lastCorrect, seen, correctStreak, updatedAt }`.
- На главной у каждого файла: число попыток, лучший и последний процент.
- Кнопка «Работа над ошибками (N)» на главной и на странице результатов: тест только из вопросов с `lastCorrect === false` среди загруженных файлов. Если N = 0, кнопка скрыта.
- *(Если останется время)* «Готовность по банку»: «не видел / ошибался / знаю» (знаю = 2 верных подряд).
- **Приёмка:** пройти тест с ошибками → «Работа над ошибками» содержит ровно эти вопросы; ответить верно → они пропадают из счётчика.

### R4. Сохранность на iOS (US-4)
- При первой загрузке файла вызывается `navigator.storage.persist()`.
- На iOS в Safari (не в режиме «на экране Домой») после первого завершённого теста один раз показывается подсказка «Добавьте тестер на экран Домой — так данные не пропадут». Подсказку можно закрыть, она запоминается.
- Есть `manifest.webmanifest` и иконки, чтобы «На экран Домой» открывал сайт как приложение.
- **Приёмка:** подсказка не показывается в standalone-режиме, на Android и на десктопе.

### R5. Измерение (US-6)
- Определение встроенного браузера Telegram по user agent и `window.TelegramWebviewProxy`; передаётся в Метрику параметром визита `inapp: telegram | instagram | none` — без идентификаторов.
- Все ссылки, которые генерирует продукт, получают `?ref=share` / `?ref=result_tg` / `?ref=group_msg`.
- Новые цели в Метрике: `mistakes_mode_start`, `attempt_saved`, `a2hs_hint_shown`, `a2hs_hint_closed`, `group_message_share`, `privacy_open`.
- **Приёмка:** в отчёте «Параметры визитов» видна доля `inapp=telegram`; отчёт по `ref` строится.

### R6. Шаринг в чат группы (US-5)
- Кнопка «Поделиться» отправляет готовый текст (RU или KZ по выбору): что это, «загрузи наш файл с вопросами», ссылка с `ref`. На телефоне — через Web Share API, на десктопе — копирование.
- **Приёмка:** текст на обоих языках вычитан носителем казахского.

## 6. Ограничения и краевые случаи

1. **iOS ITP.** Safari стирает IndexedDB и localStorage сайта после 7 дней использования Safari без визита на сайт. К следующей сессии данные пропадут у большинства пользователей iPhone. Смягчение: R4 сейчас, экспорт/импорт в Фазе 1.
2. **Встроенный браузер Telegram** хранит данные отдельно от Safari: студент, пришедший по ссылке из чата, а потом открывший Safari, «теряет» файлы. В Фазе 0 только измеряем (R5). Мягкую подсказку решаем по данным.
3. **Приватный режим.** IndexedDB может быть недоступна. Тест должен работать, сохранение молча отключается; ошибки не показываются.
4. **Общий компьютер** (компьютерный класс). Кнопка «Стереть все данные на этом устройстве» на странице `/privacy`.
5. **Переполнение хранилища** (банки с картинками). Ошибка записи показывается, данные не теряются молча.
6. **Исправленная версия того же банка.** Другой `fileId`, но вопросы матчатся по `questionId`: история не теряется.

## 8. Вход через Telegram — позиция

Вход **не делаем** ни в Фазе 0, ни в Фазе 1 на сайте. Без серверного хранения он не даёт ни синхронизации, ни напоминаний, ни рефералов: пользователь войдёт на новом телефоне и увидит пустой профиль, а это хуже, чем отсутствие входа. Единственный вариант, где вход окупается, — **Telegram Mini App**: пользователь уже авторизован через `initData`, а сама ссылка на Mini App живёт в чатах групп. Решение о Mini App — по данным R5.

**Приложение А** (дизайн на случай, если вход понадобится): Login Widget в redirect-режиме (iframe-вариант ломается ITP в Safari); проверка `HMAC_SHA256(data_check_string, SHA256(bot_token))` через `timingSafeEqual`; `auth_date` не старше 10 минут; отдельный бот (не тот, что сейчас в `/api/upload`); сессия — зашифрованная cookie (iron-session, `HttpOnly; Secure; SameSite=Lax`) только с `tg_id`, именем и `exp`; на сервере ничего не храним; после проверки redirect на чистый URL, чтобы `hash` не попал в логи Vercel; `photo_url` не хранить; logout стирает cookie и локальные данные. Перед первым входом — согласие и ссылка на `/privacy`. Нужен CSP с nonce; HTML из .docx никогда не рендерится как HTML.
